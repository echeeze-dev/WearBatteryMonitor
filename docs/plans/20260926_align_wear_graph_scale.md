# ウォッチアプリ側グラフ時間軸スケール修正計画

## 1. 目的と概要

表示形式（折れ線 vs 棒グラフ）については現状のスタイルを維持したまま、ウォッチアプリ（`:wear`）側のグラフ表示がスマホアプリのグラフと見た目・推移が一致しない不具合を修正します。

ウォッチアプリ側の `HistoryGraphFixed` コンポーネントにおける時間軸（X 軸のスケール計算）ロジックをスマホアプリ側と同等に修正し、データ蓄積量が少ない場合でも右端に圧縮されず、データが存在する区間全体で正しく推移が画面に描画されるように改修します。

---

## 2. 変更対象コンポーネント

### ウェアモジュール (`:wear`)
- **`presentation/MainActivity.kt`** `[MODIFY]` : `HistoryGraphFixed` 内の X 軸タイムライン（`startTime` / `viewportDuration`）計算ロジックの修正

### ドキュメント類 (`docs/`)
- **`docs/plans/20260926_align_wear_graph_scale.md`** `[NEW]` : 本不具合の修正計画書
- **`docs/walkthroughs/20260926_align_wear_graph_scale.md`** `[NEW]` : 本不具合修正実績のウォークスルー報告書

---

## 3. 実装ステップ

### ステップ 1: 原因分析と修正計画書の作成 (`docs/plans/`)
- 本修正計画書を作成し、ウォッチアプリ（`:wear`）側の修正方針を明確化します。

### ステップ 2: ウォッチアプリ側 `HistoryGraphFixed` の X 軸計算ロジック改修
- 固定の 3 時間前（`now - 3h`）を基準とするのではなく、表示データ内の最古のタイムスタンプ（`minDataTs`）から現在時刻（`now`）までの実際のデータ保持期間をベースに X 軸の描画位置（`x`）を計算するように修正します。
- これにより、データ数が少なく期間が短い場合でも、スマホアプリ側と同様に画面全幅を使って綺麗にグラフ推移がレンダリングされるようにします。

### ステップ 3: テスト・ビルド検証とウォークスルー報告書の作成 (`docs/walkthroughs/`)
- `:wear:assembleDebug` のビルドを実行し、エラーなく正常に完了することを確認します。
- 修正実績をまとめた `docs/walkthroughs/20260926_align_wear_graph_scale.md` を作成します。
