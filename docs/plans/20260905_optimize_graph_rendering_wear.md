# ウォッチアプリとタイルの描画・処理最適化計画（高負荷対策）

1200件のデータを扱う際のアプリ起動時のラグ（約10秒）の解消と、タイルおよびアプリのグラフ表示が乱れる問題を、データの間引き（ダウンサンプリング）によって根本的に解決します。

## 修正内容

### 1. データ受信時のダウンサンプリング導入（Wear OS アプリ）
- **[MODIFY]** `MainActivity.kt (wear)`:
    - スマホから 1200 件のデータを受信した直後の `syncHistoryFromDataMap` 処理にダウンサンプリングを導入します。
    - 受信したデータを時間軸でグルーピングし、最大 **200 件** 程度に圧縮して保持するようにします。
    - これにより、Compose の状態更新負荷が 1/6 に軽減され、起動時およびデータ更新時の致命的なラグが解消されます。

### 2. タイルの描画最適化
- **[MODIFY]** `PhoneBatteryTileService.kt`:
    - 描画処理の直前でデータを **100〜150 件** 程度にダウンサンプリングします。
    - ProtoLayout の要素生成数を劇的に減らすことで、タイルのメモリ制限回避と、表示の高速化・安定化を実現します。

### 3. グラフ描画ロジックの改善（共通）
- グルーピングされたデータに合わせて棒の幅（`barWidth`）を最適化し、物理ピクセルに綺麗に収まるように計算式を調整します。
- これにより、重なりによるボケや色の乱れ（モアレ）がなくなり、クッキリとした鮮明なグラフになります。

## 期待される効果
- **起動・更新速度**: 10秒近いラグがほぼゼロになり、スムーズな操作が可能になります。
- **視認性の向上**: 高密度すぎて潰れていたグラフが、解像度に合わせて鮮明に表示されます。
- **タイルの安定性**: データ数に関わらず、タイルが確実に、かつ高速に表示されるようになります。

## 検証計画

### 自動テスト
- `gradle_assemble_all` を実行し、ビルドエラーがないことを確認します。

### 手動確認
- 1200件のフルデータがある状態でアプリを起動し、起動直後のラグが劇的に改善されていることを確認します。
- スクロールが滑らかであることを確認します。
- タイルの表示がデータ数に関わらず瞬時に行われることを確認します。
