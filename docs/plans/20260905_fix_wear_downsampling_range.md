# ウォッチアプリのデータ間引き（ダウンサンプリング）範囲の修正計画

ウォッチ側でグラフを表示した際、スマホ側と異なり「最近のデータ」しか表示されない（左側が空白になる）問題を、間引きアルゴリズムの改善によって解決します。

## 修正内容

### [UIレイヤー - Wear OS アプリ]

#### [MODIFY] [MainActivity.kt (wear)](file:///C:/Users/uitti/AndroidStudioProjects/WearBatteryMonitor/wear/src/main/java/com/echeeze/wearbatterymonitor/presentation/MainActivity.kt)
- `syncHistoryFromDataMap` 関数のロジックを修正します。
- **現状**: 送られてきた全データ（最大1200件）のうち、最新の200件のみを抽出していました。
- **修正後**: 送られてきた全データから、**時間軸全体をカバーするように均等に**最大200件を抽出（サンプリング）します。
    - 例えば 1200件ある場合、6件ごとに1件をピックアップして 200件にします。
    - これにより、ウォッチ側の保持データ数が 200件であっても、スマホ側と同じ 12時間分（またはそれ以上）の履歴の全体像を表示できるようになります。
- **最新データの保証**: サンプリング後も、常に最新の1件は確実にリストに含めることで、現在の状態の正確性を維持します。

## 期待される効果
- ウォッチ側のグラフを表示した際、スマホ側と同じ時間範囲（1h/3h/6h/12h）全体にデータが分布し、見た目の一貫性が保たれます。
- 起動時の軽快さ（200件処理）は維持したまま、表示できる期間が劇的に広がります。

## 検証計画

### 自動テスト
- `gradle_assemble_all` を実行し、ビルドエラーがないことを確認します。

### 手動確認
- 1200件（約20時間分）のデータがある状態で、スマホ側の表示範囲を「12h」にします。
- ウォッチアプリを開き、グラフの左端から右端までデータが表示されていることを確認します。
- スマホアプリのグラフと見比べて、推移の傾向が一致していることを確認します。
