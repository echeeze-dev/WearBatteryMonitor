## 2. 目的とマルチデバイス対応推測アーキテクチャの設計

スマートフォンだけでなく、スマートウォッチや複数の Bluetooth デバイス（イヤホン等）のそれぞれを固有の識別子（Mac アドレス / ノード ID）で個別に識別し、デバイスごとのバッテリー残量推移・残り時間を高精度に算出・表示するシステムへと拡張します。

### ① スマホにおける詳細な消費影響ファクターの設計（具体案）
スマートフォン（`PhoneBatteryMonitor`）においては、以下の消費影響ファクターを履歴（`BatteryEntry`）へ追加記録し、Active（使用中）と Idle（未使用）の推測レートに反映します：
1. **画面点灯状態 (`isScreenOn`: Boolean)**:
   - 画面が ON か OFF かにより、Active 時の消費電力（バックライト＋CPU高負荷）と Idle 時の消費電力（スリープ低消費）を明確に分離します。
2. **画面バックライト輝度 (`screenBrightness`: Int, 0〜255)**:
   - ディスプレイの消費電力は輝度にほぼ比例するため、輝度が高いほど消費レートを上方修正します。
3. **バッテリー温度 (`batteryTemperature`: Float)**:
   - 温度が高い状態（発熱時）は化学的放電が加速するため、温度補正係数として推測に掛け合わせます。

※なお、スマートウォッチや Bluetooth デバイス（イヤホン等）については、OS の制限上これらの消費影響ファクターは取得できないため、純粋な残量・時間変化レートのみをベースにしたシンプル推測とします。

### ② その他の主要設計要件
1. **内部基準（10,000mAh）とユーザー入力の倍率方式**:
   - 内部計算では基準容量を `10,000mAh` として増減電流量（mAh）を算出し、ユーザーが設定した実機バッテリー容量（mAh）との比率（倍率: `userCapacity / 10000.0`）を掛け合わせて残り時間を算出します。
2. **各状態ごとの時間あたり増減電流量（mAh/h）の可視化**:
   - Active時 / Idle時 / 充電時の 1 時間あたりの増減電流量（mAh/h）をユーザーが確認できるように開示します。
3. **マルチデバイス固有識別（MACアドレス / ノードID）**:
   - `battery_history` テーブル等にて、デバイスを固有の識別子（例: イヤホンの MAC アドレス、ウォッチのノード ID）で完全に分離して保持し、デバイスごとに独立した履歴と推測結果を表示します。
4. **起動時自動起動（Boot Receiver）**:
   - 電源ON・起動完了時（`ACTION_BOOT_COMPLETED`）に BattSync を自動起動するレシーバーを新規追加します。
