# Roomデータベースによるデータ永続化の実装 - 完了報告

アプリの再起動やアップデート後もバッテリー履歴データが保持されるよう、Roomデータベースを導入しました。

## 実施した変更

### 1. 依存関係の追加
- `libs.versions.toml` に Room (2.8.4) と KSP (2.3.11) を追加。
- `mobile/build.gradle.kts` で KSP プラグインを適用し、Room のライブラリを追加。

### 2. データ永続化層の実装
- `BatteryEntry` を Room `@Entity` に変換（`timestamp` を主キーとして使用）。
- `BatteryDao`: バッテリー種別ごとの取得、挿入、および指定件数（1200件）へのトリミング機能を実装。
- `AppDatabase`: Room データベース本体を実装（シングルトンパターン）。

### 3. ロジックの更新
- `BatteryMonitorService`: 
    - 起動時にデータベースから過去のデータを一括読み込み。
    - データ追加時に自動的にデータベース保存と古いデータの削除を実行。
- `MainActivity`:
    - サービスが動いていない場合（フォアグラウンドのみの動作時）も直接データベースに読み書きするよう対応。
    - 起動時にデータベースから初期表示データをロード。

## 検証結果

### ビルド
- `gradle_assemble_all`: **成功**

### 動作確認（期待される挙動）
- アプリを強制終了しても、再起動後に過去のグラフが消えずに表示される。
- 1200件を超えた古いデータは自動的にデータベースから削除され、ストレージ容量を圧迫しない。
