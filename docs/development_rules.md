# BattSync プロジェクト AI エージェント (Gemini 等) 活用 開発・運用ルールガイドライン

本ドキュメントは、本プロジェクトにおいて **AI エージェント (Gemini 等) と人間（開発者）が連携して開発・改修・ドキュメント作成を進める際の共通運用ルール** を定義・管理するものです。

各運用ルールには固有の ID（`[R01]`, `[R02]`, ...）が付与されており、AI エージェントはチャットセッション開始時や新規作業時に本ファイルを必ず参照し、定義されたルールを厳格に遵守します。

## 2. 各ルールの詳細と遵守事項

### `[R01]` Planの事前提示と承認待ち
- **要件**: コードを編集・変更するすべての作業の前に、必ず原因分析と修正方針をまとめた計画書 (`docs/plans/YYYYMMDD_機能名.md`) を作成します。
- **遵守事項**: チャット上でユーザー様へ Plan を提示し、「進めてください」などの明示的なご承認をいただくまで、AI はソースコードの変更・編集には一切着手しません。

### `[R02]` テスト自動実行の停止
- **要件**: ユーザー様から「テストを実行してください」という明示的なご指示がない限り、Gradle の unitTest や connectedCheck などの自動テストタスクの実行を行いません。

### `[R03]` Walkthroughの作成
- **要件**: ユーザー様から Plan の承認を得てコード修正を実施した後は、必ず `docs/walkthroughs/YYYYMMDD_機能名.md` を作成して実施結果・検証結果を報告します。

### `[R04]` インプット情報および関連履歴 No の明記
- **要件**: Plan および Walkthrough の冒頭には、インプットとなったユーザー様のご発言日時、ご指示原文の引用、および関連する過去のタスク履歴 No（例: `#16`）を明記します。

### `[R05]` KDocコメントの徹底
- **要件**: 新設または改修するすべての Kotlin クラス、関数、プロパティに、KDoc フォーマット（`/** ... */`）で丁寧な日本語説明コメントを記述します。

### `[R06]` 設計書・クラス図の同期
- **要件**: システム構造の変更や機能追加が行われた際、仕様書 (`docs/design/system_overview.md`) および PlantUML クラス図 (`docs/design/class_diagram.puml`) をタイムリーに更新・同期します。

### `[R07]` ルール変更履歴の管理
- **要件**: ルールの更新・変更時は本ファイルに更新日時（例: `2026/10/10 10:35`）を追記します。廃止されたルールも消去せず、`[DEPRECATED]` タグと廃止理由を残します。

### `[R08]` Walkthroughへのコード変更前後の記載
- **要件**: Walkthrough 作成時、変更対象モジュール（`:mobile` / `:wear`）を明記し、主要な変更箇所の Diff 比較（`-` 削除行、`+` 追加行）と変更理由を記載します。

### `[R09]` 設計決定記録 (ADR) の作成
- **要件**: アーキテクチャの選定・比較や技術方針決定を行った場合、コード変更の有無にかかわらず `docs/decisions/YYYYMMDD_議題名.md` (ADR) を作成して記録・管理します。

### `[R10]` ドキュメント作成時の現在日時事前チェック
- **要件**: ドキュメント作成・改訂時は思い込みを排除するため、必ず事前にシステム現在日時（`Get-Date` 等）を確認・チェックしてからファイル作成・命名を行います。

### `[R11]` タスク対応履歴 (Task History) の登録・更新
- **要件**: 
  - **登録タイミング**: ユーザー様からのご依頼・インプット発生時（Plan 作成時）に、即座に `docs/task_history.md` に新しい履歴 No 行を `[IN_PROGRESS]` または `[PENDING]` 状態として新規追記します。
  - **完了時**: タスク完了時に対応完了日時と Walkthrough へのリンクを記載し、ステータスを `[COMPLETED]` へ更新します。
  - **対応不要時**: 議論・検討の結果「対応不要」や「取り下げ・見送り」となったタスクについてもリストから削除せず、ステータス欄に **`[CANCELLED]` または `[NOT_NEEDED]`（対応不要）** と記載し、履歴として明確に識別・保存します。

## 4. ガイドラインの運用方法

- **会話開始時の参照**:
  AI エージェント (Gemini 等) は、開発作業や問い合わせの開始時に本ファイル（`docs/development_rules.md`）を参照し、定義されたルール ID（`[R01]`〜`[R11]`）を意識して遵守します。
- **ルールの更新手続き**:
  ユーザー様から新しい運用ルールのご指示があった場合、AI エージェントは即座に本ファイルのテーブルおよび詳細セクションを更新し、更新日時（例: `2026/10/10 10:35`）と内容を記録します。
